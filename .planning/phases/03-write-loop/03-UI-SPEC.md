## Spacing Scale

Terminal spacing is measured in cells (columns for horizontal, rows for vertical).
Values mirror the existing `SpaceXS`–`SpaceXL` constants in `internal/ui/styles.go`.

| Token | Cells | Lipgloss Constant | Usage |
|-------|-------|-------------------|-------|
| xs | 1 | `SpaceXS` | Icon gap, inline separator, lock icon suffix gap |
| sm | 2 | `SpaceSM` | Compact horizontal padding (status bar sections, diff header) |
| md | 4 | `SpaceMD` | Default element horizontal padding (pane content indent) |
| lg | 6 | `SpaceLG` | Section separation, border + content gap |
| xl | 8 | `SpaceXL` | Major layout margin |
| tree | 2 per level | `TreeIndent` | YAML tree nesting indent (per level) |

Exceptions:

- Diff overlay: 1-cell left gutter for `+`/`-` prefix characters (narrower than SpaceXS rule — dictated by diff line format convention).
- Inline textinput in edit mode: no additional horizontal padding beyond the cell cursor; input fills the value column in place.

Source: `internal/ui/styles.go` (verified — all constants exist, Phase 3 inherits without change).

## Typography

Terminal typography uses cell counts and lipgloss attributes. No web font sizes.

| Role | Attribute | Lipgloss | Usage |
|------|-----------|----------|-------|
| Body | Normal weight, foreground `#cdd6f4` | `ColorFg` | Tree key names, revealed values, diff lines, help descriptions |
| Dim/secondary | Faint attribute | `DimText` | Masked value placeholders `*** (type)`, type hints, scrollbar indicators |
| Bold/emphasis | Bold attribute | `.Bold(true)` | Diff overlay section headers ("Changes", "Key"), error/warn prefix labels, confirmation prompt label |
| Accent | Normal weight, foreground `#89b4fa` | `ColorAccent` | Selected row, breadcrumb active segment, key label in help, tree indicators, match highlights |

Rules:
- Revealed values render in Body style (normal weight, `ColorFg`). The `*** (type)` hint disappears.
- The 🔓 suffix after revealed values uses `SpaceXS` (1 cell) gap then the emoji character.
- The inline textinput cursor uses terminal default cursor rendering (bubbles/textinput manages this).
- Diff removed lines use `ColorError` (`#f38ba8`). Diff added lines use `ColorSuccess` (`#a6e3a1`).
- The `y/n` confirmation prompt in the diff overlay uses Bold attribute for the key characters.

Source: `internal/ui/styles.go` (verified). Phase 3 adds `RevealedValueStyle`, `DiffAddedStyle`, `DiffRemovedStyle` — specified below.

## Color

All colors are explicit hex values. Do NOT use `lipgloss.AdaptiveColor` (confirmed hang — issue #1036, documented in `styles.go`).

| Role | Hex | Lipgloss Constant | Usage (60/30/10 split) |
|------|-----|-------------------|------------------------|
| Dominant (60%) | `#1e1e2e` | `ColorBg` | Terminal background, tree content area, diff overlay background |
| Secondary (30%) | `#313244` | `ColorSurface` | Status bar, help overlay BG, metadata overlay BG, diff overlay BG, inline textinput BG |
| Accent (10%) | `#89b4fa` | `ColorAccent` | Selected row highlight, active breadcrumb, tree expand/collapse indicators, help key labels, fuzzy match highlights |
| Success | `#a6e3a1` | `ColorSuccess` | Diff added lines (+), rotation success flash, re-encryption success flash, healthy status indicator |
| Error | `#f38ba8` | `ColorError` | Diff removed lines (−), sops subprocess error flash, hard-error box borders, destructive action label |
| Warning | `#f9e2af` | `ColorWarning` | Soft warning flash (e.g. "Reveal first with r"), unencrypted file badge |
| Muted | `#6c7086` | `ColorMuted` | Tree connectors (├─ └─ │), breadcrumb separator (`>`), dim separators, border lines |
| Foreground | `#cdd6f4` | `ColorFg` | Default text — revealed values, diff context lines, body text |

Accent reserved for (explicit list — Phase 3 additions in bold):
- Currently selected row in file list and tree
- Active breadcrumb segment
- Tree expand/collapse indicators (`[+]`, `[-]`)
- Help overlay key labels
- Fuzzy search match character highlights
- **Inline edit cursor line** (SelectedRow style = accent foreground + surface BG)

Destructive color (`ColorError`) reserved for:
- Diff removed lines (old value, prefixed with `−`)
- Sops subprocess failure flash messages
- Hard startup error box borders (established Phase 1)

Source: `internal/ui/styles.go` (verified — all constants exist). No new color values are introduced in Phase 3.

## Interaction Contract

### Key Bindings (Phase 3 additions)

| Key | Mode | Action |
|-----|------|--------|
| `r` | stateDetail, cursor on masked leaf | Decrypt and reveal single value inline. No-op if already revealed (toggles back to masked). |
| `r` | stateDetail, cursor on revealed leaf | Re-mask the value (toggle off). |
| `R` | stateDetail | Decrypt and reveal all values in current file. `R` again re-masks all. |
| `e` | stateDetail, cursor on revealed leaf | Enter stateEdit — inline textinput replaces value cell. |
| `e` | stateDetail, cursor on masked leaf | No-op — flash "Reveal first with r". |
| `Enter` | stateEdit | Confirm edit value — transition to stateDiff with single-key diff. |
| `Esc` | stateEdit | Cancel edit — restore original value, return to stateDetail. |
| `E` | stateDetail, at least one value revealed | Suspend TUI, open `$EDITOR` with decrypted temp file. On editor exit, show multi-key stateDiff if changes detected. |
| `X` | stateDetail, cursor on revealed leaf | Rotate — auto-detect format, generate new value, show in stateDiff. |
| `X` | stateDetail, cursor on masked leaf | No-op — flash "Reveal first with r". |
| `y` | stateDiff | Confirm — trigger re-encryption, return to stateDetail. |
| `n` / `Esc` | stateDiff | Cancel — discard changes, return to stateDetail without writing. |
| `j` / `k` | stateDiff (multi-key diff) | Scroll diff content up/down. |
| `Esc` | stateDetail (with revealed values) | Re-mask all revealed values, navigate back to stateFileList. |

Source: CONTEXT.md D-01 through D-14 (all locked decisions).

### State Machine (Phase 3 extensions)

```
stateDetail
  ├── r / R          → decrypt subprocess (async tea.Cmd) → update TreeNode.Revealed
  ├── e (revealed)   → stateEdit (inline textinput active)
  │     ├── Enter    → stateDiff (single-key diff)
  │     └── Esc      → stateDetail (cancel)
  ├── E (revealed)   → tea.ExecProcess($EDITOR) → EditorFinishedMsg → stateDiff (multi-key) or stateDetail (no changes)
  ├── X (revealed)   → format detect → [format menu if ambiguous] → stateDiff (rotation diff)
  └── Esc            → re-mask all → stateFileList

stateDiff
  ├── y              → sops set / sops encrypt subprocess → ReEncryptDoneMsg → stateDetail + flash
  └── n / Esc        → discard → stateDetail (no write)
```

Source: CONTEXT.md D-09, D-10, D-11; RESEARCH.md Pattern 2.

### Overlay Layout: DiffModel

The diff overlay uses the same full-screen overlay pattern as `MetadataModel` (`internal/ui/metadata.go`). Exact layout:

```
┌─ Changes: database.password ─────────────────────────────┐
│                                                            │
│  − old_value_here                                          │
│  + new_value_here                                          │
│                                                            │
│  (scrollable — j/k to scroll for multi-key $EDITOR diff)  │
│                                                            │
│  [y] confirm re-encrypt   [n/Esc] cancel                   │
└────────────────────────────────────────────────────────────┘
```

- Border: `lipgloss.RoundedBorder()`, foreground `ColorMuted`
- Header: `DiffKeyStyle` (bold, `ColorFg`) — "Changes: {key.path}"
- Removed line: `DiffRemovedStyle` (`ColorError`) — prefix `−` + 1 space + old value
- Added line: `DiffAddedStyle` (`ColorSuccess`) — prefix `+` + 1 space + new value
- Footer: `ConfirmPromptStyle` — `[y] confirm re-encrypt   [n/Esc] cancel`
- Background: `ColorSurface` (`#313244`)

Source: CONTEXT.md D-09, D-10; RESEARCH.md §Architecture Patterns.

### Inline Edit Layout

When `stateEdit` is active, the value cell in the tree row is replaced by a `bubbles/textinput` component:

```
  └─ database.password  │  [cursor here, EditInputStyle]
```

- The key column is frozen (not editable)
- The value column becomes a textinput with `EditInputStyle` (surface BG, fg text)
- No separate border — the input renders inline within the row
- Placeholder text: empty (value pre-populated from current revealed value)
- The `Enter` key triggers confirmation; `Esc` cancels

Source: CONTEXT.md D-05; RESEARCH.md Pattern 3.

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Reveal single — flash success | `Decrypted` | Status bar flash, `ColorSuccess` |
| Reveal all — flash success | `All values decrypted` | Status bar flash, `ColorSuccess` |
| Re-mask single — flash | `Value hidden` | Status bar flash, `ColorMuted` |
| Re-mask all — flash | `All values hidden` | Status bar flash, `ColorMuted` |
| Edit blocked (masked) | `Reveal first with r` | Status bar flash, `ColorWarning` |
| Rotate blocked (masked) | `Reveal first with r` | Status bar flash, `ColorWarning` |
| Re-encrypt success | `Re-encrypted` | Status bar flash, `ColorSuccess` |
| Re-encrypt failure | `Re-encryption failed: {sops stderr}` | Status bar flash, `ColorError` |
| Decrypt failure | `Decrypt failed: {sops stderr}` | Status bar flash, `ColorError` |
| Diff overlay header (single key) | `Changes: {key.path}` | DiffKeyStyle in overlay title |
| Diff overlay header (multi-key) | `Changes: {N} keys modified` | DiffKeyStyle in overlay title |
| Diff overlay footer | `[y] confirm re-encrypt   [n/Esc] cancel` | ConfirmPromptStyle |
| Rotation success flash | `Rotated to {format}` | Status bar flash, `ColorSuccess` (e.g. "Rotated to base64") |
| Format menu prompt | `Select format for new secret:` | FormatMenuStyle header |
| Format menu options | `base64 (32 bytes)`, `hex (32 bytes)`, `UUID v4`, `bcrypt (cost 12)`, `alphanumeric (32 chars)` | FormatMenuStyle items |
| Editor no changes | `No changes detected` | Status bar flash, `ColorMuted` |
| Primary CTA (diff confirm) | `[y] confirm re-encrypt` | The single unambiguous write action |

Destructive action handling:

| Action | Gate | Cancellable |
|--------|------|-------------|
| Inline edit re-encrypt | Diff overlay — `y` to confirm, `n`/Esc to cancel | Yes — Esc at any point before `y` |
| $EDITOR re-encrypt | Diff overlay — `y` to confirm, `n`/Esc to cancel | Yes — cancel in editor (save nothing) or `n` in diff |
| Secret rotation | Diff overlay — `y` to confirm, `n`/Esc to cancel | Yes — `n`/Esc in diff |

All three destructive paths funnel through the identical diff overlay gate. No inline destructive actions without confirmation.

Source: CONTEXT.md D-09, D-10, D-11, D-14; REQUIREMENTS.md EDT-04.
