## Typography

Terminal UI typography is monospace-only. Weights are rendered via lipgloss `Bold(true)` (bold) or default (regular). No configurable line-height — inherent TUI constraint.

| Role | Weight | Usage | Source |
|------|--------|-------|--------|
| Body | Regular (default terminal weight) | Recipient list rows, health finding rows, form input text, progress flash text | styles.go (pre-existing) |
| Label | Bold (`Bold(true)`) | Section headers in health overlay (Weak Secrets / Duplicates / Stale Files), overlay titles, confirmation prompt labels | styles.go (pre-existing) |

Phase 5 additions follow the same two-weight contract:
- Selection indicator `[+]` prepended to selected file names — Regular weight, accent color
- Health finding lines — Regular weight, color coded by severity
- Severity indicator labels (`[WEAK]`, `[DUPE]`, `[STALE]`) — Bold weight, severity-mapped color
- Numbered recipient list entries — Regular weight, foreground color
- Recipient diff lines (`+ age1...`, `- age1...`) — Regular weight, success/error color (reuses DiffAddedStyle / DiffRemovedStyle)
- Bulk re-key progress in status bar — Regular weight, foreground color
- Age key validation error inline — Regular weight, error color

## Interaction Contracts

### File Selection and Bulk Re-Key Flow (RCP-03)

1. User is in `stateFiles` (file list)
2. User presses `space` — `FileItem.Selected` toggles; `[+]` prefix appears/disappears on that row
3. Flash: `<N> file(s) selected. Press K to bulk re-key.` (2s)
4. User selects additional files with `space`; `[+]` prefix appears on each
5. User presses `K` — `AppModel` collects all `FileItem` where `Selected == true`
6. If no files selected: flash `Select files with space first` (2s), no-op
7. `sessionState` transitions to `stateBulkReKeyConfirm`; `bulkReKeyQueue` initialized with selected files
8. For the first file in the queue:
   - Status bar flashes `Re-keying 1/<N>: <filename>` (persistent)
   - Recipient diff overlay rendered (existing `DiffModel` layout): title `Confirm Re-key: <filename>`, shows current recipients as context lines
   - User presses `y`: `sops rotate -i <file>` is executed asynchronously; `ReKeyDoneMsg` fires
   - User presses `n` or `Esc`: file skipped, skip counter incremented
9. On `ReKeyDoneMsg`: pop next file from queue; update status bar; show next confirmation overlay
10. When queue is empty: flash `Re-key complete: <n> updated, <m> skipped` (2s); `sessionState` → `stateFiles`; clear all `Selected` flags on `FileItem` list

Source: D-05, D-06, D-07 / CONTEXT.md, RESEARCH.md Pattern 5.

### Add Recipient Flow (RCP-02)

1. User is in `stateDetail`
2. User presses `a`
3. `sessionState` transitions to `stateRecipientForm`, `prevState = stateDetail`
4. `RecipientFormModel` overlay renders full-screen: title `Add Recipient`, label `Age public key:`, `bubbles/v2/textinput` with placeholder `age1...`
5. User types a public key string; input is CharLimit 200
6. User presses `Enter`:
   - `age.ParseX25519Recipient(input)` called (client-side validation)
   - If invalid: `ValidationErrorStyle.Render("Invalid age key: " + err.Error())` appears below the input field; focus remains, no state transition
   - If valid: `sessionState` transitions to `stateRecipientConfirm`, `prevState = stateRecipientForm`
7. Recipient diff overlay renders: title `Confirm: Add Recipient`, shows `+ <pubkey>` (DiffAddedStyle) plus existing recipients as context lines
8. User presses `y`: `sops.AddRecipient(ctx, filePath, pubkey)` called asynchronously; `RecipientDoneMsg` fires
9. On `RecipientDoneMsg` success: flash `Recipient added. File re-encrypted.`; `sessionState` → `stateDetail`
10. On `RecipientDoneMsg` error: flash `Re-key failed: <sops error>`; `sessionState` → `stateDetail`
11. `Esc` at any overlay layer: return to `prevState` (confirm → form → detail)

Source: D-01, D-02, D-04 / CONTEXT.md, RESEARCH.md Pattern 2.

### Remove Recipient Flow (RCP-02)

1. User is in `stateDetail`
2. User presses `d`
3. `sessionState` transitions to `stateRecipientList`, `prevState = stateDetail`
4. Remove recipient overlay renders: title `Remove Recipient`, numbered list of `SopsMetadata.AgeRecipients`
5. If no recipients: shows `No age recipients configured for this file.`; `Esc` returns to detail
6. User presses number key `1`–`9` corresponding to recipient index
7. Selected recipient is highlighted; user may confirm by pressing `Enter` OR the number acts as direct selection
8. `sessionState` transitions to `stateRecipientConfirm`
9. Recipient diff overlay renders: title `Confirm: Remove Recipient`, shows `- <selected-pubkey>` (DiffRemovedStyle) plus remaining recipients as context lines
10. User presses `y`: `sops.RemoveRecipient(ctx, filePath, pubkey)` called asynchronously; `RecipientDoneMsg` fires
11. On `RecipientDoneMsg` success: flash `Recipient removed. File re-encrypted.`; `sessionState` → `stateDetail`
12. On `RecipientDoneMsg` error: flash `Re-key failed: <sops error>`; `sessionState` → `stateDetail`
13. `Esc`: return to `prevState`

Source: D-03, D-04 / CONTEXT.md.

### Health Check Flow (HLT-03)

1. User is in `stateFiles`
2. User presses `H`
3. Confirmation prompt inline (not full-screen overlay): `Health check requires decrypting all <N> files. Proceed? [y/n]`
4. If `n` or `Esc`: no-op, remain in `stateFiles`
5. If `y`:
   - Status bar flashes `Decrypting all files for health scan...` (persistent)
   - `HealthCheckRequestMsg` sent; `sessionState` remains `stateFiles` with a loading indicator in the status bar
   - Background goroutine: for each file sequentially, `sops.DecryptFile(ctx, path)`; failures collected in `Errors []string`; plaintext map built
   - After all files: `shannonEntropy` + format-aware checks run on each leaf value (weak); cross-file value hash comparison (duplicates, using SHA-256 hash as key, never storing plaintext in result); `GetLastCommitTime` age check (stale); plaintext map zeroed
   - `HealthCheckResultMsg` sent with findings
6. On `HealthCheckResultMsg`:
   - `sessionState` transitions to `stateHealth`, `prevState = stateFiles`
   - `HealthModel` overlay renders full-screen: `ColorSurface` background, RoundedBorder, `SpaceMD` padding
   - Sections in order: `Weak Secrets`, `Duplicates`, `Stale Files`; each section preceded by bold section header
   - Each section: findings listed (see Copywriting Contract); empty section shows no header (omit entirely)
   - Footer: skipped files notice if `len(Errors) > 0`; navigation hint `j/k scroll  H or Esc close`
7. `j`/`k`: scroll overlay one line at a time
8. `H` or `Esc`: close overlay; `sessionState` → `stateFiles`

Source: D-09, D-10, D-11, D-12 / CONTEXT.md, RESEARCH.md Patterns 3, 4, 6.

### State Machine: New States

| New State | Entered From | Exited To | Trigger to Enter | Trigger to Exit |
|-----------|-------------|-----------|-----------------|-----------------|
| `stateRecipientForm` | `stateDetail` | `stateRecipientConfirm` (valid) or `stateDetail` (Esc) | `a` key | `Enter` (valid) / `Esc` |
| `stateRecipientList` | `stateDetail` | `stateRecipientConfirm` (select) or `stateDetail` (Esc) | `d` key | number key / `Esc` |
| `stateRecipientConfirm` | `stateRecipientForm` or `stateRecipientList` | `stateDetail` (y/n/Esc) or `stateBulkReKeyConfirm` (next file) | valid input + Enter | `y` / `n` / `Esc` |
| `stateBulkReKeyConfirm` | `stateFiles` | `stateFiles` (queue empty) or next file | `K` with selected files | queue exhausted |
| `stateHealth` | `stateFiles` | `stateFiles` | `HealthCheckResultMsg` | `H` / `Esc` |

`prevState` pattern: each new state saves `prevState` on entry so `Esc` always restores the correct prior view.
Priority chain (inheriting from existing phases): search deactivation > overlay close > navigate back.

Source: RESEARCH.md Pitfall 7, CONTEXT.md §Code Context.

All new overlays follow the established `MetadataModel` / `HistoryModel` layout contract:

## Health Check Logic Contract

### Weak Secret Criteria (D-08)

A leaf value is flagged **WEAK** if ANY of the following are true:
1. `len(value) < 16`
2. `shannonEntropy(value) < 3.5` (entropy in bits per character — Claude's Discretion, RESEARCH.md A1)
3. Key name ends in `_token`, `_key`, or `_secret` AND `internal/ui.DetectFormat(value) == FormatUnknown`

The finding record contains: file path, key path, value length, entropy value (rounded to 1 decimal). The plaintext value is NOT stored in the finding.

### Duplicate Criteria (D-09)

Two leaf values across any files are flagged **DUPE** if their SHA-256 hash matches.
Finding record contains: the two (or more) `file > key.path` location pairs that share the hash. The plaintext value and the hash are NOT stored in the displayed result — only the location pairs.

### Staleness Criteria (D-10)

A file is flagged **STALE** if: `time.Since(commitTime).Hours() / 24 > threshold`.
Default threshold: 90 days. Configurable via `SOPS_TUI_STALE_DAYS` environment variable (integer, parsed at health check initiation). Files with no git history (untracked or outside a git repo): emit a `[STALE]` finding with `(no git history)` note instead of a day count.

### Handling Undecryptable Files (Claude's Discretion)

Files that fail `sops.DecryptFile` during the health scan are collected in `HealthCheckResultMsg.Errors`. They do NOT contribute to weak/duplicate checks. They are listed in the health overlay footer as `<N> file(s) skipped — could not decrypt`. No further retry is attempted; the user must resolve their key access outside the TUI.
