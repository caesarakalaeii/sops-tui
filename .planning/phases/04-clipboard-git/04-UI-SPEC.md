## Typography

Terminal UI typography is monospace-only. Weights are rendered via lipgloss `Bold(true)` (bold) or default (regular).

| Role | Weight | Usage | Source |
|------|--------|-------|--------|
| Body | Regular (default terminal weight) | File list rows, tree nodes, history entries, description text | styles.go (pre-existing) |
| Label | Bold (`Bold(true)`) | Section headers in history overlay, key labels, badge text, prompt labels | styles.go (pre-existing) |

Line height: 1 terminal row per text line (inherent TUI constraint — no configurable line-height).

Phase 4 additions follow the same two-weight contract:
- Git badge text (`[M]`, `[A]`, `[?]`) — Regular weight, color-coded
- History entry lines — Regular weight with bold short hash prefix
- Clipboard indicator in status bar — Regular weight, accent color while hot
- "no git" status bar indicator — Regular weight, muted color

| State | Indicator Text | Color |
|-------|---------------|-------|
| Clipboard holds a secret | `[clip]` | `ColorAccent` |

## Interaction Contracts

### Clipboard Copy Flow

1. User is in `stateDetail`, focused on a revealed leaf node (`TreeNode.Revealed = true`)
2. User presses `ctrl+y`
3. `clipboard.WriteAll(value)` is called synchronously
4. Flash: `Copied (clears in 30s)` appears in status bar for 2s
5. `clipboardHot = true` — `[clip]` indicator appears in status bar right section
6. `tea.Tick(timeout)` schedules `ClipboardClearMsg{Gen: n}` after timeout (default 30s, overridden by `SOPS_TUI_CLIPBOARD_TIMEOUT`)
7. On `ClipboardClearMsg`: if `gen == clipboardGen`, call `clipboard.WriteAll("")`, set `clipboardHot = false`, remove `[clip]` indicator
8. If user copies again before timeout: `clipboardGen++`, new `tea.Tick` scheduled, old tick fires but gen mismatch prevents action
9. On any exit path: `defer clipboard.WriteAll("")` in `main.go` clears clipboard regardless of timer state

Source: D-01 through D-08 / CONTEXT.md, RESEARCH.md Pattern 1.

### Git Badge Rendering

1. On startup: `go-git` `Worktree.Status()` called during file discovery phase
2. `DiscoveredFile.GitStatus` field populated: `"M"`, `"A"`, `"?"`, or `""` (clean/no git)
3. `FileItem.Title()` appends badge after filename: `filename.yaml [M]` — single space separator
4. Detail view breadcrumb appends badge after filename segment: `sops-tui > files > prod.yaml [M]`
5. After any write operation (edit, rotate, re-encrypt): git status refresh triggered via new `GitStatusRefreshMsg`
6. Non-git repo: no badges rendered, `no git` appears in status bar right section alongside env indicators

Source: D-09 through D-12 / CONTEXT.md.

### Git History Overlay

1. User presses `b` in `stateDetail`
2. `sessionState` transitions to `stateHistory`, `prevState` saved
3. Full-screen overlay rendered (same layout as `MetadataModel`): `ColorSurface` background
4. `go-git` `repo.Log(&LogOptions{FileName: &relPath})` called asynchronously, sends `GitHistoryMsg`
5. While loading: `Loading history...` shown in overlay body
6. On `GitHistoryMsg`: entries rendered — one row per commit: `hash  date  author  subject`
7. `j`/`k` scroll through entries (bubbles viewport or manual offset)
8. `b` or `Esc` closes overlay, `sessionState` returns to `prevState`

Source: D-13 through D-16 / CONTEXT.md.

### Cross-File Search (GIT-03)

1. User presses `/` from `stateFiles` (file list view)
2. Existing `SearchModel` activates with cross-file mode
3. On first activation from file list: all SOPS files parsed lazily, key lists cached in `AppModel`
4. `fuzzy.Find(query, aggregatedItems)` where each item is `"filename > key.path"`
5. Results rendered in the file list panel, replacing normal file list
6. Selecting a result navigates to that file's detail view, focused on matching key
7. `Esc` cancels search, returns to normal file list

Source: GIT-03 requirement, RESEARCH.md §Architecture Patterns.
