type Severity int

Implement `RunChecks() ([]ValidationResult, bool)` that performs ALL checks and returns ALL results:

1. **sops binary check (HLT-01, D-03 hard error):**
   - Use `exec.LookPath("sops")` to check PATH
   - If not found: append `ValidationResult{SeverityError, "sops binary not found", "Install sops: https://github.com/getsops/sops#install"}`
   - Set `hasHardError = true`

2. **age key check (HLT-02, D-03 soft warning):**
   - Build path: `filepath.Join(home, ".config", "sops", "age", "keys.txt")` where home comes from `os.UserHomeDir()`
   - Use `os.Stat` to check existence
   - If missing: append `ValidationResult{SeverityWarn, "Age key file not found", "Create key: age-keygen -o ~/.config/sops/age/keys.txt"}`
   - Do NOT set hasHardError

3. **.sops.yaml check (D-04 soft warning):**
   - Implement `findSopsYaml(startDir string) (string, bool)` that walks from startDir up to filesystem root
   - Loop: `os.Stat(filepath.Join(dir, ".sops.yaml"))`, if found return (path, true)
   - Parent: `filepath.Dir(dir)`, if `parent == dir` return ("", false) — reached root
   - If not found: append `ValidationResult{SeverityWarn, ".sops.yaml not found in current directory or parents", "Run sops-tui in a repository with a .sops.yaml configuration"}`

Export `FindSopsYaml` for reuse by later phases (file discovery). Accept `startDir string` parameter to make it testable (tests pass temp dirs, production passes `os.Getwd()`).

For testability: accept an `Options` struct or use functional options so tests can override:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PATH environment | exec.LookPath searches user's PATH — could find a malicious sops binary |
| Filesystem traversal | findSopsYaml walks up from cwd to root — reads directory entries |
| Age key file | os.Stat checks existence of ~/.config/sops/age/keys.txt — no content read in Phase 1 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Elevation | exec.LookPath("sops") | accept | Phase 1 only checks existence, never executes. Phase 3 will validate sops binary hash before subprocess calls. |
| T-01-04 | Tampering | findSopsYaml directory walk | mitigate | `filepath.Dir` loop terminates at root (parent == dir check). No `os.Open` on .sops.yaml — only `os.Stat`. No path from user input — starts from `os.Getwd()`. |
| T-01-05 | Information Disclosure | Error messages | mitigate | Error messages expose only binary names and standard paths (no secrets, no internal paths). Fix text points to public URLs. |
| T-01-06 | Information Disclosure | Age key path | accept | Only checks existence via os.Stat — never reads key content. Path is the well-known default (`~/.config/sops/age/keys.txt`). |
</threat_model>
