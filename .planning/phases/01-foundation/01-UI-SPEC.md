# Phase 1 — UI Design Contract

> Visual and interaction contract for the TUI skeleton. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> NOTE: This is a terminal UI rendered with lipgloss/ANSI — not HTML/CSS. Spacing is in terminal cells (columns/rows), not pixels. Typography maps to terminal attributes (bold, dim, normal). Colors are ANSI 256 or true-color hex values passed to lipgloss.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (TUI — not shadcn) |
| Preset | not applicable |
| Component library | bubbles v2 (`charm.land/bubbles/v2`) |
| Styling library | lipgloss v2 (`charm.land/lipgloss/v2`) |
| Icon library | none — use box-drawing characters and ASCII indicators ([+], [-], [M], ✓, ✗) |
| Font | terminal monospace — inherit from user's terminal; no override |

> **Critical:** Do NOT use `lipgloss.AdaptiveColor` — known hang (issue #1036). Use explicit hex colors throughout.

---

## Spacing Scale

Terminal spacing is in cells (columns for horizontal, rows for vertical). All values are multiples of 1 cell; horizontal padding aligns to even numbers for visual balance.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 1 cell | Icon gap, inline separator padding |
| sm | 2 cells | Compact horizontal padding (status bar sections) |
| md | 4 cells | Default element horizontal padding (pane content indent) |
| lg | 6 cells | Section separation, border + content gap |
| xl | 8 cells | Major layout margin |

Vertical spacing:

| Token | Value | Usage |
|-------|-------|-------|
| row-xs | 0 rows | Adjacent items in a list |
| row-sm | 1 row | Between list sections / group separators |
| row-md | 2 rows | Between major UI regions (reserved for future multi-pane) |

Exceptions:
- Status bar: exactly 1 row tall, full terminal width, pinned to bottom row
- Help overlay: full terminal height and width (no margin), inner content padded md (4 cells) on left/right
- Error box (stderr): padded sm (2 cells) all sides inside the border
- YAML tree indentation: 2 cells per nesting level

---

## Typography

Terminal "typography" = text rendering attributes. No font size control — terminal is monospace fixed-width.

| Role | Attribute | Usage |
|------|-----------|-------|
| Body | normal weight, no decoration | List items, key names, plain content |
| Label | bold | Section headers, pane titles, status bar labels |
| Dim | faint/dim | Secondary info: item counts, masked values (`***`), timestamps |
| Emphasis | bold + accent color | Selected list item, active breadcrumb, error keyword |

Rules:
- Maximum 2 concurrent text attributes on any single piece of text (e.g., bold + color is fine; bold + italic + underline is not)
- Underline reserved exclusively for hyperlinks in help text (e.g., URLs)
- Italic not used — poor rendering in most terminal emulators

## Color

> All colors are explicit hex. No `lipgloss.AdaptiveColor`. Dark terminal background assumed (standard developer default).

| Role | Hex | lipgloss constant name | Usage |
|------|-----|----------------------|-------|
| Background (60%) | `#1e1e2e` | `ColorBg` | Terminal background fill (set on root container) |
| Surface (30%) | `#313244` | `ColorSurface` | Status bar background, help overlay background, error box background |
| Accent (10%) | `#89b4fa` | `ColorAccent` | Reserved list (see below) |
| Success | `#a6e3a1` | `ColorSuccess` | sops/age/.sops.yaml available indicators (✓) |
| Warning | `#f9e2af` | `ColorWarning` | Soft-warning indicators (age key missing, .sops.yaml missing) |
| Error | `#f38ba8` | `ColorError` | Hard error indicators, error box border, missing sops binary |
| Muted | `#6c7086` | `ColorMuted` | Dim text, separators, borders |
| Foreground | `#cdd6f4` | `ColorFg` | Default text on dark background |

Accent (`#89b4fa`) reserved for:
- Currently selected list item highlight (background tint or foreground color on selection)
- Active breadcrumb segment in status bar left section
- Collapse/expand indicator `[+]`/`[-]` on tree nodes
- Help panel `?` keybinding key labels

Accent is NOT used for: borders, separators, general text, icons, counts, or any background fill.

60/30/10 interpretation for TUI:
- 60%: The vast majority of screen area is the terminal background (`#1e1e2e`) with default foreground text
- 30%: Status bar and help overlay use the surface color (`#313244`) as their background
- 10%: Accent appears only on selection, active breadcrumb, tree indicators, and help key labels

## Interaction Contract

This section replaces/extends standard web interaction patterns with TUI equivalents.

### Keybindings (Phase 1 scope)

| Key | Action | Context |
|-----|--------|---------|
| `j` / `↓` | Move selection down | File list, YAML tree, help overlay |
| `k` / `↑` | Move selection up | File list, YAML tree, help overlay |
| `g` | Jump to top | File list, YAML tree |
| `G` | Jump to bottom | File list, YAML tree |
| `ctrl+d` | Scroll half-page down | File list, YAML tree |
| `ctrl+u` | Scroll half-page up | File list, YAML tree |
| `Enter` | Drill into selected / expand node | File list (→ detail view), YAML tree (expand collapsed node) |
| `l` / `→` | Same as Enter for tree nodes | YAML tree |
| `h` / `←` | Collapse expanded node | YAML tree |
| `Esc` | Go back / close overlay | Detail view (→ file list), help overlay (→ current view) |
| `?` | Toggle help overlay | All views |
| `q` | Quit application | All views |

### Navigation Model

Single-pane drill-down (D-05):
```
[File List View]
  → Enter on file → [Detail View (YAML tree)]
                      → Esc → [File List View]
  → ? from any view → [Help Overlay]
                        → ? or Esc → previous view
```

No side-by-side split in Phase 1. No tabs.

### YAML Tree Rendering

Structure (D-06, D-07):
```
secret-file.yaml
  ├─ [+] database          ← collapsed group (Enter/l to expand)
  ├─ [-] api               ← expanded group (h to collapse)
  │    ├─ key: ***         ← leaf node with masked value
  │    └─ secret: ***
  └─ token: ***
```

Rules:
- Indentation: 2 cells per nesting level
- Group nodes: prefix `[+]` (collapsed) or `[-]` (expanded) in accent color
- Tree connectors: `├─`, `└─`, `│` in muted color (`#6c7086`)
- Leaf key names: foreground color, normal weight
- Values in Phase 1: always shown as `***` (no decryption in this phase)
- Selected row: accent color foreground + surface color background highlight across full width

### Startup Error Box (stderr)

Rendered with lipgloss to stderr before any TUI session (D-01):

```
┌─ sops-tui: startup failed ──────────────────────────────┐
│                                                           │
│  [ERROR] sops binary not found                           │
│  Install sops: https://github.com/getsops/sops#install   │
│                                                           │
│  [WARN]  Age key file not found                          │
│  Create key: age-keygen -o ~/.config/sops/age/keys.txt   │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

- Border style: lipgloss `RoundedBorder()`, colored `ColorError` for hard errors, `ColorWarning` for warnings-only
- All issues in one box (D-02)
- `[ERROR]` label in `ColorError`, `[WARN]` label in `ColorWarning`
- Box width: min(terminal width - 4, 72 cells)
- Padding inside border: sm (2 cells) horizontal, 1 row vertical

Hard vs soft (D-03):
- `sops` missing → `[ERROR]` in box, exit code 1, no TUI launch
- age key missing → `[WARN]` in box, TUI launches, decryption unavailable
- `.sops.yaml` missing → `[WARN]` in box, TUI launches, nothing to browse yet

### Status Bar (D-10, D-11, D-12)

Layout: 1 row, pinned bottom, full terminal width, `ColorSurface` background.

```
  sops-tui > secrets/          │  12 items  │  sops:✓  age:✓  .sops.yaml:✗
```

Sections:
- Left: breadcrumb path (`sops-tui > [view name] > [file name if in detail view]`) — active segment in `ColorAccent`, separators `>` in `ColorMuted`
- Center: item count (e.g., `12 items`, `3 keys`) in `ColorMuted`
- Right: environment indicators — each shows label + symbol. Available: `label:✓` in `ColorSuccess`. Unavailable (hard): `label:✗` in `ColorError`. Unavailable (soft): `label:⚠` in `ColorWarning`

Section separator: `│` in `ColorMuted`, padded sm (2 cells) each side.

Flash messages (D-12):
- Duration: 2 seconds, then status bar restores normal content
- Flash replaces the entire status bar content (all three sections become the message)
- Flash text: centered, foreground `ColorFg`, background `ColorSurface`
- Flash examples: `Copied to clipboard`, `Operation cancelled`

### Help Overlay (D-08, D-09)

Full-screen overlay — replaces current view content entirely.

```
┌─ Help ──────────────────────────────────────────────────────────────────┐
│                                                                           │
│  Navigation                                                               │
│  j/k         Move down / up                                               │
│  g/G         Jump to top / bottom                                         │
│  ctrl+d/u    Scroll half page down / up                                   │
│  Enter/l     Open / expand                                                │
│  Esc/h       Back / collapse                                              │
│                                                                           │
│  Global                                                                   │
│  ?           Toggle this help panel                                       │
│  q           Quit                                                         │
│                                                                           │
│  Press ? or Esc to close                                                  │
└───────────────────────────────────────────────────────────────────────────┘
```

Rules:
- Border: lipgloss `RoundedBorder()`, border color `ColorMuted`
- Background: `ColorSurface`
- Inner padding: md (4 cells) horizontal, 1 row vertical
- Section headers (`Navigation`, `Global`): bold label weight
- Key labels (e.g., `j/k`): fixed-width column (12 cells), `ColorAccent`
- Description column: normal body weight, `ColorFg`
- Contextual: file list view shows only file-list keybindings + global; detail view shows tree keybindings + global
- Footer hint `Press ? or Esc to close` in `ColorMuted`, bottom of overlay content

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Open" (Enter key on file list selection — label shown in help, not a button) |
| File list empty state heading | `No SOPS files found` |
| File list empty state body | `No .sops.yaml discovered in this directory or parents. Run sops-tui in a repository with a .sops.yaml configuration.` |
| sops missing error | `sops binary not found — Install sops: https://github.com/getsops/sops#install` |
| Age key missing warning | `Age key file not found — Create key: age-keygen -o ~/.config/sops/age/keys.txt` |
| .sops.yaml missing warning | `.sops.yaml not found in current directory or parents — TUI started but no files to browse` |
| Detail view empty (no keys) | `No keys found in this file` |
| Flash: quit | (none — app exits, no flash needed) |
| Status bar: sops available | `sops:✓` |
| Status bar: age available | `age:✓` |
| Status bar: .sops.yaml available | `.sops.yaml:✓` |
| Status bar: sops unavailable | `sops:✗` |
| Status bar: age unavailable | `age:⚠` |
| Status bar: .sops.yaml unavailable | `.sops.yaml:⚠` |
| Help overlay footer | `Press ? or Esc to close` |

Copywriting rules:
- No exclamation points — tool is used in professional/CI contexts
- Error messages always include a resolution path (install/create instruction or URL)
- Indicator symbols: ✓ for healthy, ✗ for hard error, ⚠ for soft warning
- Counts use plain English: `12 items`, `3 keys` — not `12x` or `[12]`
