Land the palette tune + 16-color profile fallback infrastructure for Phase 10:

1. **Palette tune (D-415).** Flip three hex constants in `internal/ui/styles.go`: `ColorAccentHex` `#89b4fa` → `#cba6f7` (Catppuccin Mauve), `ColorWarningHex` `#f9e2af` → `#fab387` (Catppuccin Peach), `ColorErrorHex` `#f38ba8` → `#eba0ac` (Catppuccin Maroon). All 8 named `Color*` lipgloss vars derived from these constants automatically pick up the new hex values. The named styles (`BreadcrumbActive`, `MenuKeyStyle`, `LogoStyleInfo`, `BadgeUnencrypted`, `FlashWarnBarStyle`, `FlashErrBarStyle`, etc.) inherit the new colors without further edits.

2. **16-color fallback variants (D-420).** Declare a parallel `var (...)` block of `Color*ANSI` named-ANSI fallback variants using `lipgloss.ANSIColor(N)`: Accent=13, Bg=0, Surface=8, Fg=15, Muted=7, Success=10, Warning=11, Error=9. RESEARCH.md confirms 22/24 paired bg/fg combinations in chrome PASS the 4-bit hand-verification table; 1 MARGINAL (info-panel label/value Muted=7 vs Fg=15) is mitigated by `Width(5)` + `:` punctuation structural separation; 1 WARNING (logo Warn vs Err on monochrome) is mitigated by Plan 1's `[W]/[E]` flash prefix.

3. **Palette accessor (D-421).** Declare a `Palette` struct (flat: `{Accent, Bg, Surface, Fg, Muted, Success, Warning, Error lipgloss.Color, Fallback bool}`) and a `PaletteFor(profile colorprofile.Profile) Palette` accessor function. The accessor switches on `profile <= colorprofile.ANSI` and returns the ANSI variants (with `Fallback=true`) on the fallback branch; otherwise returns the 24-bit Catppuccin Mocha variants (with `Fallback=false`). Plan 3's bracket-chip rendering reads `palette.Fallback` to gate bracket-vs-pill rendering. NOTE: D-421 in CONTEXT.md said `Palette(profile)`, but that name collides with the `Palette` struct type. Per pattern-mapper deviation, the accessor is renamed to `PaletteFor`.

4. **Profile detection at startup (D-419).** In `cmd/sops-tui/main.go`, after the Step 5 env build, call `colorprofile.Detect(os.Stdout, os.Environ())` once. Apply the `SOPSTUI_FORCE_ASCII` env var override (Claude's discretion — recommended). Pass the resolved profile into `app.NewAppModel(env, sopsYamlPath, profile)`. Promote `github.com/charmbracelet/colorprofile` from `// indirect` to a direct require in `go.mod`. Pass `tea.WithColorProfile(profile)` to `tea.NewProgram` so Bubble Tea's Cursed Renderer downsamples to the same profile AppModel uses for variant selection.

5. **Renderer signature cascade.** Add a `palette Palette` parameter to `RenderChrome`, `RenderCrumbs`, `RenderMenu`, `RenderInfoPanel` (per D-421). Plan 2 plumbs the parameter through; Plan 3 wires the bracket-fallback rendering inside `RenderCrumbs` based on `palette.Fallback`. `RenderLogo` is NOT modified — the existing `LogoStyleInfo/Warn/Error` package vars rebuild from the new hex constants automatically (per pattern-mapper deviation #5). AppModel computes `m.palette = ui.PaletteFor(m.profile)` once at construction, alongside the existing `m.infoPanel` field initialisation.

6. **Test cascade.** All 30+ `NewAppModel(env, "")` callsites in tests pass `colorprofile.TrueColor` as the third argument (TrueColor is the default lipgloss test profile, so SGR bytes in goldens stay unchanged from a render-time perspective — only the constant flip drives the diff). 4 hex-literal-using tests (`logo_test.go` 3 refs, `crumbs_test.go` 3 refs, `menu_test.go` 1 ref) are migrated to compute the expected RGB triplet from the hex constants instead of hardcoding the old `#89b4fa`/`#f9e2af`/`#f38ba8` values; this protects against future palette tunes.

**Zero behavioural change in this plan.** All current functional flows, keybindings, fallback tiers, and chrome layouts remain byte-identical except for the SGR color codes the new palette emits.
```go
package ui_test

import (
    "fmt"
    "strconv"
    "strings"
)

// hexToRGBTriplet converts a 6-digit hex color string ("#aabbcc") to the
// "r;g;b" triplet that lipgloss/v2 emits in 24-bit SGR sequences. Used by
// color-presence test assertions that need to verify a specific palette
// constant appears in rendered output, without hardcoding the literal RGB
// values (which would silently desync from D-415's palette flip).
//
// Phase 10 D-417: tests reference constants (ColorAccentHex etc.), not literals.
// This helper is the single mapping point — future palette tunes only need
// to flip the constant; tests that compare via this helper auto-update.
//
// Panics on malformed input (test-only helper; failures should be loud).
func hexToRGBTriplet(hex string) string {
    if !strings.HasPrefix(hex, "#") || len(hex) != 7 {
        panic(fmt.Sprintf("hexToRGBTriplet: malformed hex %q (expected '#RRGGBB')", hex))
    }
    r, err := strconv.ParseUint(hex[1:3], 16, 8)
    if err != nil {
        panic(fmt.Sprintf("hexToRGBTriplet: bad red component in %q: %v", hex, err))
    }
    g, err := strconv.ParseUint(hex[3:5], 16, 8)
    if err != nil {
        panic(fmt.Sprintf("hexToRGBTriplet: bad green component in %q: %v", hex, err))
    }
    b, err := strconv.ParseUint(hex[5:7], 16, 8)
    if err != nil {
        panic(fmt.Sprintf("hexToRGBTriplet: bad blue component in %q: %v", hex, err))
    }
    return fmt.Sprintf("%d;%d;%d", r, g, b)
}
```

This helper lives in `package ui_test` (same as the existing tests). Other `*_test.go` files in the same directory can call it directly without import.
