# Phase 7.1: Code Review Report

**Reviewed:** 2026-04-27
**Depth:** standard
**Files Reviewed:** 17
**Status:** issues_found (info-only)

## Summary

Phase 7.1 (chrome-skeleton gap closure) is structurally clean. The five
gap-closure deliverables — SC5 governance revert, menu allowlist + quit-hint
docs, sub-model border strip + NewStyle lift, BFS reachability AST walker,
and narrow-terminal chrome 3-tier clamp — are implemented coherently with
clear inline rationale.

Key correctness checks:

- The "no `lipgloss.NewStyle()` reachable from any View()" contract is
  preserved across all reviewed sub-model files (`diff.go`, `health.go`,
  `help.go`, `history.go`, `metadata.go`, `recipientform.go`) and across
  helpers reachable from `AppModel.View()` (`renderRecipientList`,
  `renderFormatMenu` in `model.go`). All previously inline styles are
  declared as package vars in `styles.go`. Both AST walkers
  (`TestViewNoNewStyle` BFS in `chrome_test.go` and
  `TestSubmodelViewsNoNewStyle` per-file in `submodel_view_no_newstyle_test.go`)
  will report zero violations against the reviewed sources.
- The narrow / mid / full chrome tier formulas in `RenderChrome` are
  internally consistent: narrow boundary 25 + 2*8 = 41, full boundary 38 + 25
  + 2*18 = 99. Mid-tier `menuWidth = width - logoWidth` is bounded below by
  the narrow-tier guard so it never goes below `2 * minMenuCol`.
- Hint sets in `internal/keys/hints.go` (`RecipientConfirmHints`,
  `BulkReKeyConfirmHints`, `RecipientListHints`, `FormatMenuHints`,
  `FileListSearchHints`) match the dispatcher in `AppModel.menuHints()`,
  including the deliberate quit suppression on the two confirm states.
- The bench-budget gate is correctly skipped (`t.Skip` first; the
  `testing.Short()` short-circuit is unreachable but harmless) with
  governance rationale recorded in the doc-comment.

No critical or warning issues. Six info-level findings below are stale-comment
and dead-code artifacts that do not affect runtime behaviour but obscure
intent and would mislead a future reader (or AST walker maintainer) about
the actual implementation.

**File:** `internal/ui/chrome_test.go:227-228, 250-251, 286-287`
**Issue:** Three `TestRenderChrome_*` doc comments cite the pre-Plan-05
threshold formulas (`width < 33`, `33 <= width < 71`, `width >= 71`) that
were superseded when Plan 05 introduced `minFullMenuCol = 18` and the new
boundaries 41 / 99. The actual test inputs (30, 60, 200) still fall in
the correct tiers and the assertions still hold, but the comments now
contradict the code in `chrome.go:107-116`.

**Fix:** Update each comment block:

```go

// fallback per Phase 7.1 D-116: single-line "press ? for help" stub.

// TestRenderChrome_DropsInfoPanel asserts the mid-tier (41 <= width < 99)

// TestRenderChrome_FullChrome asserts the full-tier (width >= 99)
// 3-slot layout per Phase 7.1 D-116: info-panel + menu + logo, exactly
// 6 rows tall.
```

### IN-04: Dead-code branch on `versionVal` in MetadataModel.buildContentLines

**File:** `internal/ui/metadata.go:91-94`
**Issue:** The block

```go
versionVal := m.meta.Version
if versionVal == "" {
    versionVal = ""
}
```

assigns `""` to a value that is already `""`. The conditional is a no-op.
Other empty fields in the same function (`enc regex`, `unc regex`,
`recipients`) take the `MetadataNoneStyle` "(none)" branch when empty;
`version` does not, so the empty-string guard is vestigial. Likely a
leftover from an earlier `(none)` plan that was reverted.

**Fix:** Either drop the no-op `if`:

```go
lines = append(lines, labelStyle.Render("version")+valueStyle.Render(m.meta.Version))
```

…or, if the intent was to render `(none)` for empty version (matching
the regex fields), wire it up explicitly:

```go
if m.meta.Version == "" {
    lines = append(lines, labelStyle.Render("version")+none)
} else {
    lines = append(lines, labelStyle.Render("version")+valueStyle.Render(m.meta.Version))
}
```

The current form claims to do something but does nothing.

### IN-05: Dead `menuWidth < 1` clamp in RenderChrome full tier

**File:** `internal/ui/chrome.go:127-130`
**Issue:** The full-tier branch is gated by
`width >= infoPanelWidth + logoWidth + menuCols*minFullMenuCol` (i.e.
`width >= 99`). At width=99 the computed `menuWidth = width - infoPanelWidth -
logoWidth = 36`, which is `2 * minFullMenuCol` — the minimum possible. The
`if menuWidth < 1 { menuWidth = 1 }` clamp can therefore never fire. It
also masks any future regression where the tier guard formula and the
slot widths drift out of sync.

**Fix:** Either drop the unreachable clamp:

```go
menuWidth := width - infoPanelWidth - logoWidth
menu := RenderMenu(hints, menuWidth)
```

…or convert it to a static invariant assertion (panic) so a future
mismatch fails loudly instead of silently rendering a 1-col menu:

```go
menuWidth := width - infoPanelWidth - logoWidth
if menuWidth < menuCols*minFullMenuCol {
    panic("RenderChrome full-tier menuWidth invariant violated; tier guard mismatch")
}
```

The current `< 1` floor obscures the actual invariant (`>= 36`).

### IN-06: BFS walker keys funcs by name only — collision risk acknowledged but unguarded

**File:** `internal/app/chrome_test.go:175-187`
**Issue:** `TestViewNoNewStyle` keys the `funcs` and `fileOf` maps by
`fd.Name.Name` only. The comment at lines 180-184 explicitly notes:
"If a future package adds a non-AppModel method named View(), the BFS
would falsely follow it; tighten then." The walker is otherwise
defensible (the comment acknowledges the gap), but the failure mode is
silent — a same-name collision overwrites the `funcs` entry and the BFS
walks the wrong body, producing either false negatives (missed
violations) or misleading file-path attribution in the violation list.

**Fix:** Defensively detect the collision so the test fails loudly when
the assumption breaks. After the FuncDecl loop, check for duplicates:

```go
for _, decl := range f.Decls {
    fd, ok := decl.(*ast.FuncDecl)
    if !ok || fd.Body == nil {
        continue
    }
    if _, dup := funcs[fd.Name.Name]; dup {
        t.Fatalf("BFS walker collision: function %q declared in both %s and %s; "+
            "rekey funcs map by (recvType, name) to disambiguate",
            fd.Name.Name, fileOf[fd.Name.Name], path)
    }
    funcs[fd.Name.Name] = fd
    fileOf[fd.Name.Name] = path
}
```

This is the minimum-cost guard and matches the "tighten then" intent in
the existing comment.
