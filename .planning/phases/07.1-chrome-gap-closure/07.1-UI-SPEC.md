# Phase 7.1 — UI Design Contract (Delta)

> **This is a delta spec.** The canonical chrome design contract lives in
> `.planning/phases/07-chrome-skeleton/07-UI-SPEC.md` and is unchanged by Phase 7.1.
> Phase 7.1 implements the existing 07-UI-SPEC contract more faithfully (single
> border per overlay, narrow-terminal survival) and adds two small new contract
> items below.

## Inherited from 07-UI-SPEC

All visual tokens, layout grids, and interaction patterns from
`07-UI-SPEC.md` apply unchanged. In particular:

- 6-row chrome envelope: `[info-panel-placeholder | menu | logo]`
- 2×6 keybinding menu grid; `MenuKeyStyle` + `MenuDescStyle` per cell
- Titled body wrapped via `WrapTitled` using `lipgloss.NormalBorder()`
- ASCII-only chrome; no rounded corners, no emoji, no ZWJ

## Phase 7.1 Additions

### A. Single-border framing for overlay states (closes WR-02)

**Contract:** `HelpModel`, `MetadataModel`, `DiffModel`, `HealthModel`,
`HistoryModel`, `RecipientFormModel` `View()` methods return inner content
only — no inner border, background, or padding envelope.
`WrapTitled` (from `internal/ui/chrome.go`) is the **single source of border
chrome** for these 6 states.

**Why this is a contract change vs. an implementation fix:** Phase 7's
implementation drifted from 07-UI-SPEC (which never authorised double
borders) by leaving sub-model inner borders in place. Phase 7.1 brings the
implementation back into spec. Goldens at 120×40 and 200×60 now show one
titled border per overlay, not two nested borders.

**Carve-out:** `stateFormatMenu` continues to render its own
`RoundedBorder` overlay (transient modal) and is opted out of `WrapTitled`
at `model.go:1336-1337`. This carve-out is unchanged from Phase 7.

### B. Narrow-terminal chrome fallback (closes WR-03; partial coverage of UI-16)

**Contract:** `RenderChrome(hints, status, width)` falls back through
three width tiers:

| Tier | Width range | Layout |
|------|-------------|--------|
| Full | `width >= infoPanelWidth + logoWidth + minMenuCol` (~71+) | `[info-panel-placeholder | menu | logo]` (existing 3-slot) |
| Mid  | `logoWidth + 8 <= width < 71` | `[menu | logo]` — info-panel slot dropped |
| Narrow | `width < logoWidth + 8` (~33) | One-line `press ? for help` stub |

**Why this is a contract addition:** 07-UI-SPEC §"narrow-terminal aesthetics
deferred to Phase 10 (UI-16)" defers *aesthetic* polish to Phase 10 but did
not specify behaviour for *content overflow* at narrow widths. Phase 7's
unspecified behaviour (cell-wrapped menu rows pushing the body off-screen
at 40×12 and 80×24) is a regression vs. the implicit "body must remain
reachable" contract. Phase 7.1 closes this with the explicit three-tier
fallback above.

**Out of scope (still Phase 10):** Color-aware narrow palette, breadcrumb
ellipsis behaviour, 16-color terminal rendering. Phase 7.1 only addresses
the binary "chrome fits / chrome doesn't fit" question.

### C. Confirm-flow quit-hint suppression (closes WR-05)

**Contract:** In `stateRecipientConfirm` and `stateBulkReKeyConfirm`, the
persistent menu intentionally **omits the `[q] quit` hint**. The user must
resolve the y/n decision before exiting to prevent accidental
acknowledgement of a partially-actioned destructive flow.

**Affected hint sets:**
- `keys.RecipientConfirmHints` — 5 entries, no `q`
- `keys.BulkReKeyConfirmHints` — 5 entries, no `q`

**Visible-everywhere-else default unchanged:** `DiffModel.Hints()` still
includes `[q] quit` (6 entries) in `stateDiff` because that state is purely
informational (no pending destructive action).

**Implementation note:** Phase 7's behaviour already implements this via
the dispatcher arms at `model.go:1466-1469`. Phase 7.1 makes the
*intentionality* explicit by adding inline doc comments on the hint
declarations and the dispatcher arms.
